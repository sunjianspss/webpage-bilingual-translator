# 网页双语翻译

一个支持 Chrome、Edge 和 Safari 的 Manifest V3 双语网页翻译扩展。它提取当前网页的可见正文，调用本地 OpenAI 兼容 API 或 DeepSeek API，并在原网页中显示双语译文。

## 功能

- 全页正文翻译
- 双语对照与仅译文模式
- 一键恢复原文
- 本地 OpenAI 兼容 API
- 自动检测本机的 LM Studio / Ollama / llama.cpp / vLLM / Jan：点“自动检测”即可填好 API 地址，并把已加载的模型列成下拉，不用手打模型名
- DeepSeek API
- 翻译进度与错误提示（失败提示会带上第一条真实原因，而不只是失败数量）
- 开翻前先探活本地服务：服务没启动、需要 API Token、模型名和已加载的对不上，都在第一秒说明原因，不会跑完整页才报失败
- 页面正文分批发送，API Key 不进入网页上下文
- 翻译结果按“页面 + 目标语言”缓存到 `chrome.storage.local`，刷新页面无需重新翻译（缓存上限约 3000 条，超出后淘汰最早写入的条目）
- 只在目标书写系统可靠可识别时自动跳过已是目标语言的正文（日语假名、韩文）；汉字无法靠字符范围区分中/日和简/繁，因此会交给翻译服务，避免静默漏译
- “清除缓存并重译”按钮：换模型或对译文不满意时，一键清除当前页面的缓存并强制重新翻译，不影响其他页面的缓存
- 本地 API 使用紧凑输入、动态 token 上限、首批预热和后续 4 路 worker，减少本地模型等待时间
- DeepSeek 长页面使用 6 路批次并发，本地 API 首批预热后使用 4 路 worker
- 快捷键翻译当前页面：Windows/Linux `Ctrl+Shift+Y`，macOS `Command+Shift+Y`
- 模型返回格式异常时自动拆分批次重试
- 仅在用户打开扩展时向当前页面注入翻译脚本
- X.com 等动态页面会自动补扫可见内容

## 隐私

扩展没有服务器、没有账号、没有任何统计代码。页面正文只发往你自己选择的
翻译服务（本机的模型服务，或 DeepSeek），请求里不含页面网址、标题或任何
用户标识。完整说明见 [PRIVACY.md](PRIVACY.md)。

## Chrome / Edge 安装

1. 打开 `chrome://extensions/` 或 `edge://extensions/`。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本项目根目录。
5. 安装后刷新需要翻译的网页。

## Safari 安装

Safari 版本位于 `safari/网页双语翻译/`，需要使用 Xcode 构建。开发测试可运行：

```bash
./script/build_and_run.sh
```

长期正式使用需要 Apple Developer 证书签名。未签名扩展只适合本机开发调试。

## 本地 API

默认配置适配 LM Studio 提供的 OpenAI 兼容接口：

```text
API 地址：http://127.0.0.1:1234/v1
模型：qwen/qwen3.5-35b-a3b
```

“高质量推理”默认关闭。本地 LM Studio 会收到 `reasoning_effort: "none"`，DeepSeek 会收到
`thinking: { "type": "disabled" }`。开启后两种服务都使用推理模式；
长句和术语通常更稳，但整页翻译会明显变慢。其他本地服务若不支持
`reasoning_effort`，可以开启“高质量推理”。

如果 LM Studio 开启了“Require Authentication”，请在扩展中填写对应
API Token。

### 上下文长度与并行槽

扩展单次请求的上限是 18 个片段 / 4200 字符输入，加上最多 4096 个输出
token，峰值约 7.5K token。**每个推理槽的上下文长度设到 8192 即可，推荐
16384 留出余量。** 设得更大不会更快 —— 批次上限是固定的，多出来的窗口
一次也用不到，反而让 KV cache 白占显存；把模型权重挤到 CPU 上之后，单
批很容易撞上 45 秒的请求超时。

设得比 8192 小则会出问题：模型输出被截断，扩展会判定成格式错误并把批次
二分重试，整页明显变慢。这种情况下需要同步调小 `src/content/state.js` 里的
`LOCAL_BATCH_CHARACTER_LIMIT` / `LOCAL_BATCH_SEGMENT_LIMIT` 和
`src/shared.js` 里的 `DEFAULT_MAX_TOKENS`。

扩展对本地服务使用 4 路并发。如果本地服务只有一个推理槽，这 4 个请求会
排队逐个处理，并发不生效 —— 但这只影响整页速度，不会导致失败。

**只有当这个本地服务是专供本扩展使用时，才建议把并行槽数开到 4。**
llama.cpp 系的服务会把上下文按槽平分，因此填的上下文长度需要是
“单槽长度 × 槽数”（例如 4 槽 × 16384 = 65536）。

如果同一个服务还要给别的 agent 类工具用（例如跑在同一个
`127.0.0.1:1234` 上的编码助手、桌面 agent），请优先照顾它们：那类工具的
上下文随会话累积增长、没有固定上限，而且超出窗口通常直接返回 500 硬失败，
而本扩展的需求封顶在 ~7.5K、窗口不足时只会退化成变慢。这种情况下应保持
单槽并把整个窗口留给对方，不要为本扩展开并行槽。

### 排查：翻译很慢或大面积超时

大窗口的 KV cache 会占用可观的显存。如果它把模型权重挤出显存、导致部分
层被卸载到 CPU，生成速度会掉一个量级，而扩展的单请求超时是 45 秒
（`TRANSLATION_REQUEST_TIMEOUT_MS`，见 `src/background.js`），慢到一定
程度就会大面积报“翻译服务请求超时”。

判断方法：在本地服务里看模型加载后的 GPU/CPU 分配（LM Studio 的模型信息
面板会显示 GPU offload 层数），或者用下面的实测基准对照 —— 预热批是最灵敏
的探针，它固定只有 5 个片段，正常应在 3 秒内返回，要是涨到十几秒，基本就是
显存不足在拖。

参考基准（MacBook Pro / Apple M5 Pro / 48GB，LM Studio 单推理槽，
`qwen/qwen3.5-35b-a3b`，“高质量推理”关闭）：

| 场景 | 耗时 |
| --- | --- |
| 预热批（5 段 / 688 字符） | 2.3s |
| 常规批（18 段 / 2299 字符） | 7.7s |
| 满负载批（13 段 / 4199 字符，撞字符上限） | 12.8s |
| 整页（120 段 / 20760 字符，8 个批次） | 首句上屏 3.4s，全部完成 69.7s |

换算成吞吐约 **300 源字符/秒**。这个数值在单批、4 路并发、整页三种场景下
几乎不变，说明瓶颈是模型的生成吞吐，而不是请求往返次数 —— 也因此，调大
批次上限并不会让整页变快（满负载批实测只比常规批高约 10%），却会抬高模型
漏译、触发二分重试的概率。

同样的原因，单推理槽下扩展的 4 路并发拿不到收益：实测 4 批并发 32.3s、
4 批串行 36.4s，加速比仅 1.12x，请求实际是在服务端排队。要让并发真正生效
只能靠增加推理槽，代价见上一节。

按代价从低到高处理：

1. 调低本地服务的上下文长度（在满足其他共用工具需求的前提下），KV cache
   随之变小；
2. 开启本地服务的 KV cache 量化（如 Q8），显存占用约减半；
3. 换更小或量化程度更高的模型。

不建议直接调大 `TRANSLATION_REQUEST_TIMEOUT_MS` —— 那只是把超时失败换成
长时间无响应，整页翻译的体感反而更差。

Ollama 通常可使用：

```text
API 地址：http://127.0.0.1:11434/v1
模型：填写 Ollama 中已安装的模型名称
```

其他服务只要实现 `POST /chat/completions`，并返回 OpenAI Chat
Completions 结构，也可以直接使用。

## DeepSeek

选择“DeepSeek API”，填写 API Key。默认模型为
`deepseek-v4-flash`，也可切换到 `deepseek-v4-pro`。

## 本地验收服务

这个模拟服务只验证扩展的请求、批处理和页面渲染链路，不评估翻译质量：

```bash
node scripts/mock-openai-server.mjs
```

然后把扩展 API 地址临时改为 `http://127.0.0.1:11434/v1`，模型名可任意
填写，翻译结果会以“测试译文：”开头。

## 开发检查

```bash
npm test
npm run check
```

`src/content.js` 是生成文件，由 `src/content/` 下的模块拼接而成（content
script 必须以单文件注入）。修改内容脚本时请编辑 `src/content/` 中的源文件，
然后运行：

```bash
npm run build-content
```

该命令会重新生成 `src/content.js` 并同步 Safari 侧文件；测试会校验生成物
与模块源码保持一致。

## MVP 限制

- 默认最多翻译当前页面前 220 个唯一正文片段。
- 继续滚动后出现的新内容可再次点击翻译。
- 复杂站点可能因自身 CSS 导致少量排版变化。
- API Key 保存在 `chrome.storage.local`，适合个人使用；团队产品应改用后端代理。
