# v0.1.4 - Packaged Releases, Persistent Cache, Faster Translation

The second release of 网页双语翻译. Installing no longer requires cloning the
repository: a ready-to-load extension package is attached to this release.

## Highlights

### Installation is now a download

Earlier releases were source archives that had to be unzipped and loaded as an
unpacked extension from the repository root, which also carried the tests, build
scripts and the Xcode project. This release attaches a package containing only
the twelve files the browser actually reads.

### Translations persist across reloads

Results are cached per page and target language in `chrome.storage.local`, so
reloading a page no longer retranslates it. The cache holds about 3000 entries
and evicts the oldest past that. A "clear cache and retranslate" button drops
the cache for the current page only, for when you switch models or dislike a
translation.

Text already in the target language is detected by CJK character ratio and
skipped rather than sent to the model.

### Failures explain themselves, and explain themselves early

Before translating, the extension probes the local backend with a single
`GET /models`. An unreachable service, one that requires an API token, and a
model name that is not loaded each fail within the first second with the reason.
The healthy-path cost is about 37ms. Failure notices now carry the first real
error instead of only a count, and the keyboard-shortcut path reports errors in
the page status bar instead of only the service-worker console.

### Faster first line and faster page

Local batch concurrency went from 2 to 4, measured at 1.20x against a real local
model, and candidate collection is no longer quadratic. The small warmup batch
runs on every scan, which puts the first translated line on screen at about 2.9s.

### Correctness fixes

- One-segment batches whose model output was a bare object or an id-to-text map
  used to lose that text permanently, because a one-segment batch cannot be
  split and retried.
- Manifest V3 recycles the service worker after 30s idle while the request
  timeout is 45s. In-flight requests now keep it alive.
- The top of long documents went untranslated once the 220-segment budget bound,
  because list items lower on the page consumed the quota first.
- Duplicate translation blocks no longer appear under the same paragraph.

See `CHANGELOG.md` for the full list.

## Installation

### Chrome / Edge

1. Download `webpage-bilingual-translator-0.1.4.zip` from this release and unzip it.
2. Open `chrome://extensions/` or `edge://extensions/`.
3. Enable Developer mode.
4. Click "Load unpacked".
5. Select the unzipped folder.
6. Refresh any page you want to translate.

### Safari

Safari support is included as an Xcode project under `safari/网页双语翻译/`.

For local development:

```bash
./script/build_and_run.sh
```

For long-term everyday use, Safari requires signing with an Apple Developer
certificate.

## Configuration

Default local API settings:

```text
API URL: http://127.0.0.1:1234/v1
Model: qwen/qwen3.5-35b-a3b
```

The extension works with OpenAI-compatible `POST /chat/completions` services.
DeepSeek users should select "DeepSeek API" in the popup and enter their API key
locally in the browser extension.

If LM Studio has "Require Authentication" enabled, fill in the matching API
token in the extension.

## Verification

The release was checked with:

```bash
npm run check
npm test
npm run package
```

All passed before tagging. The package contents were confirmed to carry
`manifest.json` at the archive root with no build or test files included.

## Known Limits

- The default page cap is 220 unique visible text segments.
- Newly loaded content after scrolling can be translated by clicking the
  translate action again.
- Complex site CSS may still cause small layout differences.
- API keys are stored in browser extension local storage, which is suitable for
  personal use. Team deployments should use a backend proxy.
- The extension is not yet listed on the Chrome Web Store, so installation still
  goes through Developer mode.
